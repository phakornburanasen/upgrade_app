# TNLX Software Updater

A central Go update server and a Windows client update agent.

- The update server listens on `0.0.0.0:45000` and serves releases from `source_path` (`Z:\` on Windows, `/mnt/appl/Program` on Linux).
- The client agent opens a local browser UI on `http://127.0.0.1:45100`.
- Client updates install into `C:\tnl_appl\<ApplicationName>`. The previous version is backed up to `C:\tnl_appl\_backup` first.
- The client never reads `Z:` and never uses SMB. All transfers go through the update server over HTTP.
- v1 has no database, no version check, and no ZIP package step.

## Project layout

```text
cmd/
  update-server/          central update server
  update-agent/           client agent (local HTTP server + UI)
  start-update-agent/     Start_update_agent.exe launcher
  encrypt-agent-config/   encrypts config\agent.json -> config\agent.enc
internal/
  server/                 server config and API
  agent/                  agent config, config encryption, update jobs
  agentui/                embedded client UI (index.html, static/)
config/
  server.json             server config (Windows)
  server-linux.json       server config (Linux)
  agent.json              client config (plain)
  agent.enc               client config (encrypted, generated by build.bat)
docs/                     API, configuration, deployment, security, troubleshooting
```

## Build

Run the build script from the project root:

```powershell
.\build.bat
```

It runs `go test ./...`, then produces:

| Output | Purpose |
|---|---|
| `bin\update-server.exe` | Update server for Windows |
| `bin\linux-amd64\update-server` | Update server for Linux (amd64) |
| `bin\client-update.exe` | Client agent, no console window |
| `bin\client-agent.exe` | Copy of `client-update.exe`, started by the launcher |
| `bin\client-update-console.exe` | Client agent with a console window, for debugging |
| `bin\encrypt-agent-config.exe` | Config encryption tool |
| `Start_update_agent.exe` | Launcher for end users |
| `config\agent.enc` | Encrypted copy of `config\agent.json` |

Close any running agent before building, because the script has to replace the `.exe` files.

## Configuration

Server (`config\server.json`):

```json
{
  "host": "0.0.0.0",
  "port": 45000,
  "source_path": "Z:\\",
  "log_path": "logs\\update-server.log"
}
```

Each folder directly under `source_path` is published as one application.

Client (`config\agent.json`):

```json
{
  "host": "127.0.0.1",
  "port": 45100,
  "server_url": "http://10.0.32.71:45000",
  "install_path": "C:\\tnl_appl",
  "temp_path": "C:\\tnl_appl\\_update",
  "backup_path": "C:\\tnl_appl\\_backup"
}
```

### Encrypted client config

`build.bat` encrypts `config\agent.json` into `config\agent.enc` (AES-GCM). The agent reads either format. `Start_update_agent.exe` uses `agent.enc` when it exists and falls back to `agent.json`.

To re-encrypt after editing `agent.json` without a full build:

```powershell
.\bin\encrypt-agent-config.exe -in config\agent.json -out config\agent.enc
```

The key comes from the `TNLX_AGENT_CONFIG_KEY` environment variable, or a built-in key if it is not set. If you set a custom key, set the same value on every machine that runs the agent. This encryption only stops casual reading of the config; it is not a strong secret store. See [docs/SECURITY.md](docs/SECURITY.md).

To deploy to clients, copy `Start_update_agent.exe`, `bin\client-agent.exe` and `config\agent.enc`. You don't need to copy `agent.json`.

## Run

Server:

```powershell
.\start_update_server.bat
```

On Linux:

```bash
./bin/linux-amd64/update-server -config config/server-linux.json
```

Client (end users): double-click `Start_update_agent.exe`. It starts the agent in the background and opens the UI in the default browser. If the agent is already running, it just opens the UI.

Client (debugging, with logs in a console window):

```powershell
.\start_update_agent.bat
```

## Client UI

The UI uses the TNLX Endpoint Monitor theme: a dark navy navbar with the TNLX logo, teal accents, and white rounded cards.

Each application is shown as a compact card:

- **Icon:** the program's initials. A dark tile means installed; a light grey tile means not installed.
- **Status:** `Installed`, `Not installed`, or `Up to date` after a successful update.
- **Button:** `Install` (solid teal) when `C:\tnl_appl\<ApplicationName>` does not exist yet, or `Update` (teal outline) when it does. After a successful install, the button changes to `Update`.
- **Selecting:** click a card to select it (the icon turns into a ✓). Selected apps are listed in **Selected Systems**, where you can remove them with ×.

Toolbar actions:

- **Search program:** filter by name or path.
- **Update Selected:** install or update the selected apps.
- **Update All:** install or update every app on the server.
- **Check All:** reload the application list from the server.

The **Update Progress** panel and the popup at the top show the current application, stage (downloading, backing up, installing), file count and bytes.

## Update flow

For each application the agent:

1. Gets the file list from the server.
2. Downloads every file into `temp_path\<App>\<JobID>`.
3. Backs up the existing `install_path\<App>` to `backup_path\<App>\<timestamp>` (skipped for a new install).
4. Copies the downloaded files into `install_path\<App>`.
5. Restores the backup if the copy fails, then removes the temporary folder.
